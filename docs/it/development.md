# Разработка

Как устроен код сайта «Совпало» и как его запустить. Решения о стеке — в [ADR-0001](architecture/adr/0001-tech-stack-and-architecture.md).

## Что нужно

- Node.js 24 LTS (версия в `.nvmrc`).
- pnpm через Corepack: `corepack enable` или `corepack pnpm …` перед каждой командой. Версия pnpm закреплена в `package.json`.
- Docker — для локальной базы PostgreSQL 18.

## Первый запуск

```bash
corepack pnpm install
cp .env.example .env.local
corepack pnpm db:up
corepack pnpm db:migrate
corepack pnpm import:brands data/brands.sample.json
corepack pnpm dev
```

Сайт откроется на http://localhost:3000. База из `docker-compose.yml` слушает порт **5433**, чтобы не мешать другим PostgreSQL на машине.

Реальный файл брендов кладём в `data/brands.json`: папка `data/` в `.gitignore`, в репозитории лежит только `data/brands.sample.json` с вымышленными брендами.

| Команда | Что делает |

## Импорт брендов

Формат — выгрузка базы «Бренды», `schema_version: "1.0"`. Схема описана в `src/import/schema.ts`, из неё генерируется `schemas/brands.schema.json` для подсказок в редакторе.

- Сначала проверяется весь файл. Если есть ошибка, в базу ничего не пишется, а команда печатает бренд, поле и причину.
- Затем upsert по `id` в одной транзакции. Бренды, которых нет в файле, уходят в статус `hold`; флаг `--keep-missing` это отключает.
- Новые значения справочников (темы, стили, декор, посадки, техники, ценности) создаются сами. Короткие названия и цвета тем берутся из `src/lib/taxonomy.ts`.
- `--dry-run` проходит тот же путь и откатывает транзакцию, поэтому отчёт совпадает с настоящим запуском.
- Повторный запуск с тем же файлом ничего не меняет: импорт сравнивает хеш данных бренда. В журнал `imports` пишутся только запуски с изменениями.
- В выгрузке 1.0 нет статуса и цвета бренда. Схема принимает необязательные `status` (`showcase | hold | reserve`, по умолчанию `showcase`) и `color` (`#RRGGBB`).

## Устройство кода

```
src/
  app/                    страницы и обработчики (Next.js App Router)
    page.tsx              каталог: фильтры слева, карточки справа
    brands/[id]/          страница бренда /brands/<id>/
    temy/[slug]/          посадочная с включённой темой /temy/<тема>/
    dlya-brendov/         «Для брендов»
    go/[brand]/[shop]/    переход в магазин: +1 в click_daily и 302
    robots.ts, sitemap.ts, llms.txt/
  components/             карточка, фильтры, обложка-макет, JSON-LD
  db/                     схема Drizzle и подключение
  import/                 схема файла и импорт из JSON
  lib/                    фильтры в адресе, поиск, ссылки, подписи справочников
  server/services/        сервисный слой: brands, clicks
  proxy.ts                X-Robots-Tag: noindex до открытия каталога
scripts/                  консольные команды: импорт, миграции, проверка файла
drizzle/                  SQL-миграции
```

Страницы не ходят в базу напрямую, только через `src/server/services`. Запись брендов (`upsertBrand`, `refreshSearchVectors`) — там же; через неё работает импорт, позже будет работать админка.

### Каталог и фильтры

- Фильтры — обычная форма GET, параметры в адресе: `q`, `tema`, `stil`, `posadka`, `tkan`, `cena`, `kupit`. Без JS фильтр применяется кнопкой «Показать», с JS — сразу при выборе.
- Случайный порядок задаёт сид `p` в адресе. Он появляется при первом применении фильтра и сохраняет порядок, пока посетитель фильтрует. В браузер ничего не пишется (FR-2).
- Метка кампании Директа `c` передаётся через внутренние ссылки и попадает в счётчик переходов.

### Поиск

Полнотекстовый поиск PostgreSQL с конфигурацией `russian`. `brands.search_vector` собирается сервисом из названия, тем, стиля, декора, посадки, ткани, города, ценностей, места производства и описания. Каждое слово запроса ищется ещё и как начало слова. Совпадения в названии и описании подсвечивает `ts_headline`.

### Похожие по вкусу

Блок на странице бренда (FR-10), функция `similarBrands` в `src/server/services/brands/read.ts`. Правило перенесено из прототипа v1.3.

- Кандидаты — все остальные бренды витрины (`showcase`).
- Каждому начисляются баллы за совпадения с текущим брендом: общая тема — 2, общий стиль — 1, общий декор (надпись, принт, вышивка и т. п.) — 0,5.
- В блок попадают бренды с суммой от 1,5, не больше трёх, по убыванию суммы. При равной сумме порядок случайный, свой для каждого открытия страницы.
- Значит, одной общей темы достаточно, а одному общему стилю нужен ещё хотя бы общий декор.
- Цена, посадка, ткань, город и место покупки не учитываются. Если подходящих брендов нет, блок не показывается.

### Переходы в магазины

Кнопка магазина ведёт на `/go/<бренд>/<магазин>/?from=…&c=…`. Счётчик `click_daily` увеличивается только для GET с Referer нашего домена (`SITE_URL`) и без бот-User-Agent. IP, cookie и User-Agent не хранятся. К ссылке добавляются UTM-метки, кроме Telegram и VK.

### Переменные окружения

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | Подключение к PostgreSQL |
| `SITE_URL` | Публичный адрес сайта: canonical, sitemap, проверка Referer |
| `SITE_INDEXING` | `false` до открытия каталога: noindex и запрет в robots.txt |
| `SITE_STAGE` | `preview` — полоса «Предпросмотр каталога» и блок «Это ваш бренд?» |

`SITE_INDEXING` и `SITE_STAGE` читаются при запросе, поэтому один образ работает и на staging, и на prod. `SITE_URL` дополнительно попадает в `metadataBase` при сборке.

## Известные ограничения

- **Оформление — заглушка.** Стили перенесены из прототипа v1.3, шрифт системный. Гарнитура выбирается вместе с дизайном и подключается через `next/font/local`.
- **Обложки — простые макеты.** Иллюстрации прототипа не перенесены.
- **Статус 404.** Включены Cache Components с частичным пререндером, поэтому несуществующий бренд или тема отдаются со статусом 200, страницей «Такой страницы нет» и `noindex`. Если нужен настоящий 404, проверку можно перенести в `proxy.ts`.
- **Промокоды** хранятся в `brand_shops.promo_code`, но в выгрузке 1.0 их нет и к ссылкам они пока не добавляются.
- **Нет пока:** staging (добавим позже), HTTPS и бэкапа на сервере (см. [deploy.md](deploy.md)), формы «Была проблема», ссылок на анкету и оферту.
